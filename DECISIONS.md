# DECISIONS.md

One line per significant decision: what, why, when.

- 2026-07-17: Build the collaboration app in a new sibling repo (this one) instead of inside Belin 1.0.0. Reason: the new app needs URL routing, an organizations-with-members model, PWA, i18n and PDF generation from day one, none of which exist there, and 60 percent of that codebase is CRM dead weight for this product.
- 2026-07-17: Belin 1.0.0 is read-only reference material. Reason: harvest deliberately (API hardening patterns, cooperation schema, email and storage patterns, domain seed data) without inheriting baggage.
- 2026-07-17: Visual identity comes from AVE-DC (Poljubinj dashboard design tokens and components), then upgraded significantly. Reason: proven, distinctive system already built for exactly this domain; founder wants elite 2026-Q3 quality.
- 2026-07-17: Companies are organizations with member roles inside them (EPC: CEO or admin, Bauleiter; sub: owner, crew; later a marketing role for the CRM upsell). Reason: multi-seat collaboration cannot work on Belin 1.0.0's one-user-equals-one-company model.
- 2026-07-17: Zero-manual-entry principle for the EPC: plan PDF upload with automatic extraction of project facts, EPC reviews and edits instead of typing. Full interactive plan viewer stays out of v1. Reason: adoption depends on the EPC not becoming busier than before.
- 2026-07-17: The § 15 VOB/B 6-working-day countersigning clock, Nachtrag pre-approval gate and compliance expiry logic are modeled as explicit product mechanics. Reason: market research shows no competitor implements them; sharpest differentiator.
- 2026-07-17: Pilot target: a real project of a German EPC starting 22.07.2026, with AVESOL as subcontractor. Plan a brutally minimal slice for that date while designing for the full vision.
- 2026-07-17: EU data residency (Supabase Frankfurt), DPA with customers, no worker personal documents through non-EU AI APIs. Reason: GDPR compliance as described in HANDOFF.md section 8.
- 2026-07-17: Monday 20.07 demo scope approved (docs/specs/2026-07-17-monday-demo-design.md): daily log with quantity-based progress, EPC live dashboard, Stückliste check, tokenized links instead of auth. Reason: demo in front of a potential customer needs the core promise, not accounts.
- 2026-07-17: Stack: Next.js App Router + Supabase Frankfurt + Vercel, PWA, German-first i18n. Reason: matches AVE-DC so the visual system and PDF rendering transfer directly; boring, proven.
- 2026-07-17: Progress is computed from weighted scope items with target quantities, logged daily by the crew. Reason: turns percent complete into evidence and later powers Abschlagsrechnung documentation (§ 16 VOB/B, § 632a BGB); no competitor does this.
- 2026-07-17: Stückliste check is a required gate before daily logging starts; EPC is auto-notified of complete or missing materials. Reason: catches missing material on day one, when it is cheap, and demos the two-way flow.
- 2026-07-17: Sub can request materials, plans, or instructions in-app (first candidate to slip past Monday if time runs short). Project address gets an "In Google Maps öffnen" button. Reason: founder additions from the field.
- 2026-07-17 (evening): Timeline corrected: the Monday 20.07 demo is in Slovenian for a Slovenian EPC prospect; the German EPC tests the full v1 with real accounts from 27.07, replacing the 22.07 pilot start; v1 complete by Sunday 26.07 evening. Reason: founder update in the scope session.
- 2026-07-17 (evening): UI in Slovenian, German and English from the first commit. Reason: Slovenian demo Monday, German test the week after, and i18n keys from day one make three locales cheap.
- 2026-07-17 (evening): One continuous v1 build ordered demo-critical first, with a Sunday 19.07 18:00 dry-run pivot rule and an upside rule (surplus time pulls accounts work forward). Full articulation: docs/specs/2026-07-17-v1-build-order.md. Reason: protects the nearest immovable date while building only permanent foundation.
- 2026-07-17 (evening): Complete v1 data model designed and migrated up front, before module code. Reason: the five modules share entities heavily and the domain is fully specified, so schema-once prevents the migration churn that breeds bugs.
- 2026-07-17 (evening): All data access goes through a server-side actor abstraction (token actor now, auth session actor from M1). Reason: demo tokens and later magic-link auth swap without touching module code.
- 2026-07-17 (evening): Working discipline and logging system mandated: extreme care in foundation code, CHANGELOG.md for every change, docs/sessions/ log per chat session, session start and end rituals in CLAUDE.md. Reason: founder mandate to prevent bugs and preserve knowledge across sessions.
- 2026-07-17 (evening): External clocks start on day one: Supabase Frankfurt project, Vercel live URL, Resend sending-domain DNS verification. Reason: DNS and domain verification run on lead times we cannot compress later.
- 2026-07-17 (night): Stack confirmed after a challenge to reconsider it: Next.js stays the v1 and beyond foundation for both the mobile crew app and the desktop EPC dashboard. Crew capture screens will be client-side and local-first (offline queue, sync on next open); the EPC dashboard stays server-rendered. If native app-store apps are needed later, the named path is Capacitor wrapping the same web app. Reason: preserves the AVE-DC CSS design system and the @react-pdf PDF engine (React Native and Flutter would discard both), PWA-via-link is lower-friction adoption than an app-store install and matches the free-for-subs model, EU iPhone home-screen PWAs are confirmed working (Apple reversed the 2024 DMA removal), and the offline-driven client-first split for crew screens is the same architecture a future Capacitor wrap needs, so no rework. Full analysis in the session log.
- 2026-07-17 (night): Provisioning done directly via connectors: deleted the stray Supabase belin-app project (Ireland, wrong region, empty), created project belin in eu-central-1 Frankfurt, applied the full schema and buckets, seeded the Slovenian demo, created a Resend sending key, pushed the private GitHub repo TovarisKajuh/belin-app, and deployed to Vercel via GitHub import (every future deploy is now automatic on git push). Reason: the founder enabled Supabase, Vercel and Resend connectors for autonomous setup.
- 2026-07-17 (night): Both account views (EPC and sub) are built fully responsive for phone and laptop. This revises the original spec's "EPC desktop-first, sub mobile-first" split. Reason: founder expects EPCs to use the phone version too, so every screen must work well on both, mobile-first but never desktop-broken.
- 2026-07-17 (night): A development-only party-swap button lets one person jump between the connected EPC view and sub view of the same seeded project while building, so the founder can review both intertwined sides and give feedback. It is removed before launch, when magic-link auth separates the two accounts. Reason: in production the two views are never shown to the same person, so a dev swap is the only way to build and review both against one connected project. Tracked as removal debt in CHANGELOG.md.
- 2026-07-17 (night): Daily-report submission goes through one transactional Postgres function (submit_daily_report) that validates scope-item and photo-path ownership, computes the site-local date server-side, and writes entry, quantities, photos and activity atomically and idempotently. Project status changes use a compare-and-swap. Reason: a legal-evidence app must not trust client-supplied identifiers, orphan photos on a partial write, or corrupt its own audit trail under a two-device race (audit findings H1, H2, H3).
- 2026-07-17 (night): The token-transport refactor (server actions reading identity from request context instead of a client-passed token) is deferred to M1 and done together with the magic-link session actor, not twice. The material-check "latest vs one-per-project" model is deferred to phase 1b when that screen is built (a history-log index is the safe default in place). Reason: articulated in docs/audits/2026-07-17-pre-phase-1b-audit.md part 3; avoid refactoring working code twice or pre-deciding a product model.
- 2026-07-17 (night): Project lifecycle states are draft, active, paused, reviewing, finished, cancelled, governed by a tested state machine (lib/project-status.ts) enforced both in the UI and server-side. EPC transitions: pause/resume/finish/cancel and, from a review, accept (finished) or send back (active). Sub transitions: request review (active to reviewing) and withdraw (reviewing to active). Finished and cancelled are terminal for now (reopen can be added later). Reason: founder request for a shared status control that both parties see and act on; it is the anchor for Regiestunden and the auto-generated final report to come. Every change is logged to the activity feed for the live dashboard.
- 2026-07-19: Develop in Slovenian only while a feature is still being iterated; translate to German and English in one deliberate pass once the founder calls the feature done. New i18n keys are still added to all three catalogs (so the parity test keeps guarding structure) but de and en hold the Slovenian string as a placeholder until then, tracked as debt in CHANGELOG.md. Reason: founder mandate. Producing three polished languages for UI that is still changing shape makes every iteration slower and spends tokens on wording that gets discarded on the next revision.
